# Slothlet Vine v1.4.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

v1.4.0 adds CommonJS entries and a real build. Up to v1.3.0 the package was plain ESM published straight from `src/`, and `require()` only worked through whatever interop the runtime or bundler provided. Every public entry point (the root, each `transport/*` and `testing`) now ships a built ESM bundle in `dist/` and a thin `.cjs` beside it that loads that bundle through Node's synchronous `require(esm)`, so `import` and `require()` get the same module instance.

The package now declares `engines.node` `>=22.22.0`. v1.3.0 declared no Node.js requirement at all, so this is a real requirement change even though it ships in a minor release; see [Breaking Changes](#-breaking-changes) and the upgrade notes.

The vine runtime itself is unchanged: `grow()`, `serve()`, the transports, the error taxonomy, the frame format and the `@cldmv/slothlet` `>=3.22.0` peer range are all the same as v1.3.0.

## 💥 Breaking Changes

### Node.js `>=22.22.0` is now required ([#101](https://github.com/CLDMV/slothlet-vine/pull/101))

v1.3.0 had no `engines` field. v1.4.0 sets `engines.node` to `>=22.22.0`. The new build toolchain no longer runs on Node.js 20 (tsup 9 alone declares `^22.18.0 || ^24.11.0 || >=26.0.0`), so older versions can't be built or tested any more; 22.22.0 is the oldest version the CI and publish matrices now test. The `.cjs` entries throw `ERR_REQUIRE_ESM` naming `>=22.22.0` on a Node.js without `require(esm)`.

npm prints an `EBADENGINE` warning when installing on an older Node.js, and the install fails when `engine-strict` is set.

## ✨ Features

### CommonJS entries for every subpath ([#101](https://github.com/CLDMV/slothlet-vine/pull/101))

Each public entry now has a `require` condition: `@cldmv/slothlet-vine`, `@cldmv/slothlet-vine/transport/loopback`, `/transport/post-message`, `/transport/worker-threads`, `/transport/process`, `/transport/websocket` and `/testing`. Each `.cjs` is a few lines: a guard that throws `ERR_REQUIRE_ESM` with the supported range when `process.features.require_module` is missing, then `module.exports = require("./<entry>.mjs")`. There is no second CommonJS bundle, so a value required from CommonJS is the same object an ESM import gets, and `VineError` checks work across both. `main` and `module` now point at `dist/index.cjs` and `dist/index.mjs`.

### A real tsup build ([#101](https://github.com/CLDMV/slothlet-vine/pull/101))

`build` used to be an `echo` stub. It is now tsup (`tsup.config.mjs`): one minified ESM bundle per public entry, written to the same relative path under `dist/` as its source under `src/`, with function and class names kept (so `VineError.name` and stack traces read the same), `node:` specifiers kept, and the optional `ws` peer left external. tsup's `onSuccess` copies each `src/<entry>.cjs` verbatim beside its bundle.

The published `files` are now `dist/` (without source maps) and `schemas/`; `src/` no longer ships. `prepack` runs the build, so `dist/` is never committed.

### `slothlet-vine-dev` export condition ([#101](https://github.com/CLDMV/slothlet-vine/pull/101))

Every export subpath carries a `slothlet-vine-dev` condition that points `import` and `require` at `src/`. In a checkout of this repository, `node --conditions=slothlet-vine-dev` runs the unbuilt source; without the condition the entries resolve to `dist/`, which `npm run build` produces. Installed copies only ship `dist/`, so the condition has no effect there.

## 🔧 CI & tooling

- `build:ci` runs `lint`, `format:check` and the tsup build, and the coverage legs build with it (`coverage_build_command: "npm run build:ci"`) ([#101](https://github.com/CLDMV/slothlet-vine/pull/101)).
- The bundle-size check measures the built `dist/**.mjs` / `dist/**.cjs` output plus `schemas/**` instead of `src/**` ([#101](https://github.com/CLDMV/slothlet-vine/pull/101)).
- The CI and publish test matrices start at Node.js 22.22.0, the new package floor ([#101](https://github.com/CLDMV/slothlet-vine/pull/101)).
- vitest runs with the `slothlet-vine-dev` condition (resolve, SSR resolve and worker `nodeOptions`), so the suite tests `src/`; coverage counts `src/**/*.mjs` only ([#101](https://github.com/CLDMV/slothlet-vine/pull/101)).

## 🧪 Tests

- `npm test` and `ci:coverage` also run `test:dist`, which builds and runs `tests/cjs/entry.test.cjs` with `node --test` against `dist/`: each `dist/<entry>.cjs` re-exports its `.mjs`, is a verbatim copy of its `src/` file, every `exports` subpath points at a file the build produced, and a vine grown over the built CommonJS entries forwards a call ([#101](https://github.com/CLDMV/slothlet-vine/pull/101)).
- `cjs-entries.test.vitest.mjs` checks the CommonJS root against the ESM error taxonomy, carries frames over a loopback pair created through CommonJS, and checks the `ERR_REQUIRE_ESM` guard; `package-surface.test.vitest.mjs` follows the new `exports` shape ([#101](https://github.com/CLDMV/slothlet-vine/pull/101)).

## Upgrade notes

- **Node.js `>=22.22.0` is required.** Upgrade Node.js before upgrading the package. On an older Node.js, stay on [v1.3.0](./v1.3.0.md).
- ESM consumers need no code change: every `import` path resolves to the same exports as v1.3.0, now from `dist/`.
- CommonJS consumers can `require()` any entry directly instead of going through bundler or runtime interop.
- Code that reached into `src/` by file path (outside `exports`) must switch to the documented entry points, since `src/` is no longer published.

Closes [#99](https://github.com/CLDMV/slothlet-vine/issues/99).
