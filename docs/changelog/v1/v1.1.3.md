# Slothlet Vine v1.1.3 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `next` → `master`

---

## Overview

A transport fix. The worker-threads, post-message, process and websocket transports used to drop any frame that arrived before `grow()` / `serve()` registered a handler. A consumer that created a channel, awaited something such as a slothlet boot or a config load, and only then called `grow()` lost the far side's one-shot `surface` frame and failed the handshake with `VINE_BUDGET`. Those frames are now held and replayed. The wire protocol and the `grow()` / `serve()` API are unchanged.

---

## 🐛 Bug Fixes

### Transports buffer early frames until a handler is registered ([#42](https://github.com/CLDMV/slothlet-vine/pull/42))

All four transports attach their inbound listener eagerly in `createChannel()`, but discarded frames received before the vine core called `onMessage()`. They now route inbound frames through a shared pre-handler inbox (`src/lib/inbox.mjs`):

- Frames that arrive with no handler are queued, then replayed in arrival order on the next microtask once a handler is registered.
- A frame that arrives during a pending replay joins the end of the queue.
- `close()` discards the queue.

Each transport declares `buffersUntilHandler: true`, and the Channel conformance suite asserts it.

Loss **before** `createChannel()` attaches any listener belongs to the medium, not the vine. A `worker_threads` Worker and a `ws` socket deliver a message to no one when no listener exists, while a Node `MessagePort` and a `ChildProcess` queue it. The transport docs now state that the channel must be created in the same tick as the worker or socket, before any `await`.

## 🔧 CI & tooling

- **Worker e2e attaches the channel before booting the grow side** ([#39](https://github.com/CLDMV/slothlet-vine/pull/39)). The worker-threads e2e helper spawned the Worker, awaited the grow-side boot, and only then attached the channel. Under load that raced the Worker's surface frame and failed the handshake intermittently. The helper now boots the grow side first.
- **v4 workflows synced to the CLDMV/.github v4.29.0 templates** ([#38](https://github.com/CLDMV/slothlet-vine/pull/38)). Each workflow now declares read-only permissions at the top level and grants write scopes per job. The sync also adds `ci.yml`'s lint/format autofix inputs and the missing standard workflows (`dependabot-recreate`, `member-auto-merge`, `pr-notify`, `provenance`), and corrects workflow header metadata.

## Upgrade notes

No breaking changes; this is a drop-in replacement for v1.1.2. Creating a channel and attaching `grow()` / `serve()` after an `await` now works on every built-in transport. The channel itself must still be created in the same tick as its worker or socket.
