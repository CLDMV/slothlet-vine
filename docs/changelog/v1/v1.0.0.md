# Slothlet Vine v1.0.0 Changelog

**Release Date**: August 2026
**Release Type**: Major (first real release)
**Branch**: `next` → `master`

---

## Overview

v1.0.0 is the first real release of `@cldmv/slothlet-vine` — the pre-implementation scaffold published as `0.1.0` is superseded entirely (#2). It delivers the full v1 spec: **`grow()`/`serve()`** with settle-once call correlation, per-call budgets, safe-path enforcement, and data-only enforcement in both directions; the versioned **frame protocol** and **error taxonomy** (`VineError` / `VineRemoteError`); a reusable **Channel conformance harness** (published as `@cldmv/slothlet-vine/testing`); and all **five built-in transports** — `loopback`, `post-message`, `worker-threads`, `process`, and `websocket` — implemented and tested end-to-end over their real boundaries, not mocks.

A mounted stub is indistinguishable from a real leaf to slothlet itself, including for permission gating: a rule targeting `exts.foo.bar` gates the forwarding stub exactly as it would gate the real leaf, before the call ever reaches the wire.

The published tarball ships runtime code only (`src/`, `schemas/`, `README.md`, `LICENSE`) — tests, docs, and configs stay out of the package.

## ✨ Features

### Core forwarding: `grow()` and `serve()`

`serve(api, channel, options)` publishes a slothlet instance's callable leaves to the far side of a `Channel`; `grow(api, channel, options)` mounts one forwarding stub per published leaf, at the identical dotted path, onto a local slothlet instance via `api.slothlet.api.add()`. Calls correlate by `callId`, settle exactly once, and are bounded by a per-call budget so a call **never hangs forever**, even against a far side that never answers. A handshake budget (`handshakeMs`) covers the initial leaf-manifest exchange itself.

### Data-only, enforced in both directions

A function anywhere in a call's arguments or its return value is refused at the edge with a named error (`VINE_DATA_ONLY`) rather than silently failing as an opaque clone error, or — over a by-reference transport — handing the caller a live closure over the other side's scope. The rule is enforced grow-side before a stub ever sends a frame, and independently re-checked serve-side on both the return value and the incoming arguments, so a frame built directly against a by-reference channel (bypassing the stub) is refused too.

### Five built-in transports

- `slothlet-vine/transport/loopback` — same-process, by-reference; the reference implementation the conformance suite runs against.
- `slothlet-vine/transport/post-message` — browser `Worker` / `MessagePort` (structured clone).
- `slothlet-vine/transport/worker-threads` — Node `worker_threads`.
- `slothlet-vine/transport/process` — Node `child_process` IPC.
- `slothlet-vine/transport/websocket` — network, JSON codec.

Each declares its own `capabilities` (structured-clone fidelity, codec, buffering behavior) and ships as its own subpath export, so a consumer's dependency graph only pulls in what it actually imports (`ws` stays an optional peer dependency, needed only by the websocket transport).

### Channel conformance harness

`@cldmv/slothlet-vine/testing` exports a framework-injected, reusable test suite for verifying a custom `Channel` implementation against the same contract the five built-in transports are held to — buffering behavior, close semantics, and the uniform three-way send-failure policy.

## 🐛 Hardening

Most of what round out this release are defense-in-depth fixes found during review, grouped by theme rather than listed commit-by-commit:

- **Channel handler retention, closed on every exit path, not just the happy one.** `grow()` and `serve()` release their `onMessage`/`onClose` registrations on a clean `close()`, on the far side going gone after the link is already live, and on a handshake that fails before a link is ever returned — the last of which has no `close()` a caller could otherwise reach, so the failure path itself has to be the release. `transport/websocket`'s pre-open send backlog (`pendingSends`) is cleared the same way, including when the socket reports death before ever reaching `open`.
- **`transport/process`'s teardown tolerates a minimal target.** `createParentChannel`'s `proc` parameter is documented as test-double-friendly and validated only for `send`/`on`, but `close()` unconditionally called `removeListener()` — now a small `off()` helper prefers `target.off`, falls back to `removeListener`, no-ops if neither exists, and tolerates a removal that itself throws.
- **Websocket transport specifics**: `send()` checks the local-close/`readyState` state _before_ encoding, so a close race is a silent no-op regardless of what the frame contains; `connect()` validates the resolved `WebSocket` is actually a constructor before calling `new` on it; `createChannel()` rejects a socket missing a numeric `readyState` or shaped as an `EventEmitter` (which silently drops every inbound frame instead of raising an error).
- **Wire-level correctness.** `schemas/frame.schema.json` now requires a non-empty `callId` on `call`/`result`/`error` frames, matching `parseFrame`'s existing runtime rejection — the schema is the normative reference and was looser than the implementation it describes. `findFunctionArg`'s Map-key label no longer stringifies a live object key, which could otherwise invoke a hostile key's user-defined `toString()`/`Symbol.toPrimitive` on an entirely ordinary, data-only call.

None of the above are behavior changes for a well-formed caller — every one is a hardening of an edge case (retention, malformed input, a minimal or hostile far side) that a correct, cooperative caller never hits.

## 🧪 Tests

Full suite green at **flat 100% coverage** — statements, branches, functions, and lines — across every source file, including the raw branch/statement maps for each hardening fix above (not just line coverage). Every transport runs the shared Channel conformance suite plus a full six-point end-to-end bar against real slothlet instances: `loopback` in-process, `post-message` over a real `worker_threads` `MessageChannel` structured-clone hop, `worker-threads` over a real `Worker`, `process` over a real forked child, and `websocket` over a real `ws` connection on an ephemeral port.

## Upgrade notes

- **This is the first real release.** `0.1.0` was a pre-implementation scaffold — every export, every transport, and the entire wire protocol are new. There is no meaningful migration path from `0.1.0`; treat this as a first install.
- **No API stability guarantee changes.** This is the v1 surface described in [DESIGN.md](../../DESIGN.md); nothing here narrows or breaks it.
