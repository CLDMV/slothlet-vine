# Slothlet Vine v1.5.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

v1.5.0 ships TypeScript declarations. The package now includes a `types/` folder of `.d.mts` files generated from the JSDoc in `src/`, and every export carries a `types` condition that points at the matching file, so `import { grow, serve } from "@cldmv/slothlet-vine"` and each transport subpath type-check in TypeScript and show up in editor completion without any `@types` package.

The vine runtime is unchanged: `grow()`, `serve()`, the transports, the error taxonomy, the frame format and the peer ranges behave as in v1.4.1. The source changes are type annotations, casts and small refactors made so the code passes a strict type-check. The release also includes the dev-condition test fix and a 100% coverage gate for the test suite.

---

## ✨ Features

### Type declarations in `types/` ([#114](https://github.com/CLDMV/slothlet-vine/pull/114))

- `types/` is published (`files`), and `package.json` gets a top-level `"types": "./types/src/index.d.mts"`.
- Every entry in `exports` (`.`, `./transport/loopback`, `./transport/post-message`, `./transport/worker-threads`, `./transport/process`, `./transport/websocket` and `./testing`) has a `types` condition pointing at its declaration file, both on the default `import` / `require` path and inside the `slothlet-vine-dev` condition, so checkouts resolve types too.
- The shared shapes are exported from the root declarations as `SlothletControl`, `SlothletApi`, `EventMeta`, `EventListener`, `Subscription` and `EventSurface`.
- `types:build` (`tsc -p .configs/tsconfig.json --noCheck`) generates the declarations from the JSDoc, and `types/` is checked in and ignored by prettier and eslint. `@types/node` and `@types/ws` are added as dev dependencies for the type-check.
- The source passes a strict type-check (`strict`, including `noImplicitAny`, with `checkJs`). That took casts and a few small rewrites, none of which change behavior: `VineError` copies its detail fields with `Object.assign`, the frame parser reads the incoming message through a `Record` cast, and the event forwarder tests `typeof resolved !== "string"` where it used to test for a `then` method on the resolved level.

Resolves [#113](https://github.com/CLDMV/slothlet-vine/issues/113)

## 🔧 CI & tooling

- **`types:check` is the type-check script** ([#114](https://github.com/CLDMV/slothlet-vine/pull/114)). It runs `tsc -p .configs/tsconfig.json --noEmit`, and CI runs it in the type-check step, which was skipped before. `build:ci` now runs `types:check` and `types:build` between format and build.
- **Tests run against `src/` through `devCondition()`** ([#111](https://github.com/CLDMV/slothlet-vine/pull/111)). `.configs/vitest.config.mjs` set `test.nodeOptions` to pass `--conditions=slothlet-vine-dev` to the test workers, but vitest has no such option, so the condition never reached them. The config now builds on `devCondition()` from `@cldmv/configs`, which sets the resolver conditions and the worker `execArgv`.

## 🧪 Tests

- **100% coverage is enforced** ([#115](https://github.com/CLDMV/slothlet-vine/pull/115)). The suite now covers every line, branch, function and statement in `src/`, with new unit tests for events, frames, serve and the principal, and the vitest config fails the coverage run below 100% on each of the four. The runner executes each test file in its own process and merges the results, so the threshold applies to the merged report and to plain `vitest --coverage` runs, and is skipped for the per-file blob runs.
- `package-surface.test.vitest.mjs` checks the `types` conditions and the `types/` file entry ([#114](https://github.com/CLDMV/slothlet-vine/pull/114)).

## Upgrade notes

- No breaking changes — drop-in for v1.4.1. TypeScript users get types automatically; JavaScript users see no difference.
- TypeScript needs a `moduleResolution` that reads `exports` (`node16`, `nodenext` or `bundler`) to pick up the per-subpath types.
