# Slothlet Vine v1.2.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Serving to a peer the host cannot trust. Until now a vine assumed an authenticated, cooperative far side: `serve()` answered every `call` frame with host standing, and trusted the subscriber identity that the far side sent with every `sub` frame. A page script with a socket could therefore call anything in the served surface and claim any subscriber identity.

v1.2.0 adds a **channel principal**. The host binds a caller identity to the channel, taken from the transport's own authentication. slothlet's rules then decide what that identity may call and subscribe to, and the vine enforces the decision before anything runs or crosses. A per-call **`around`** wrapper lets the host run each accepted call inside its own scope: a transaction under the bound actor, a deadline, an audit record.

Both options are opt-in. Without them, every frame and outcome is exactly as in v1.1.x, and the wire format is unchanged. The `@cldmv/slothlet` peer floor rises to `>=3.22.0`, the release that adds the call gate the principal needs.

## ✨ Features

### Channel principal for calls and event subscriptions ([#53](https://github.com/CLDMV/slothlet-vine/pull/53), [#33](https://github.com/CLDMV/slothlet-vine/issues/33))

`serve(api, channel, { principal })` takes `string | { path, context? } | () => either`. The function form is called once per frame, so a host can rotate identity on re-auth without re-serving.

- **Calls.** Every `call` frame is judged as `principal.path` calling the leaf with the frame's own `args`, through `api.slothlet.permissions.global.checkCall` (slothlet 3.22.0). The check runs inside a `context.scope` that carries `principal.context`, with every top-level key write-protected, so conditional rules, `requires` principals and the leaf all see the same actor and none of them can reassign it. A refused call answers the new **`VINE_DENIED`** error and the leaf never runs. The order is: `VINE_NO_LEAF` → `VINE_DENIED` → args data-only check → invoke → return data-only check.
- **Events.** Every `sub` frame is resolved as the principal. A null subscriber path now means the channel itself, not the host. A subscriber path the far side sends is honoured only at or under the principal's path, and only to _narrow_ the level (the lower of the two). A forged claim can cost the far side deliveries but never gain it any. An `unsub` that arrives while a subscription's level is still resolving cancels it cleanly.
- **`grow({ principal })`** binds the same identity for the grow end's event server-half. The trusted end of a channel is not always the serving end, for example a host that grows leaves out of an untrusted worker plugin.
- **Fails closed at setup.** `serve({ principal })` throws a `TypeError` before publishing anything when the instance's permission system isn't enforcing, `checkCall` is missing, or `context.scope` doesn't work. A principal on an instance that can't enforce it would gate nothing, so it is refused rather than degraded.

`serving.principal` exposes the bound value for diagnostics. Each refused frame is audited on the serving instance's lifecycle bus with `via: "checkCall"`: `permission:denied` for a rule deny, and `permission:default` (under `audit: "verbose"`) for a default-policy deny. Worked call and subscription tables are in [docs/PERMISSIONS.md](https://github.com/CLDMV/slothlet-vine/blob/master/docs/PERMISSIONS.md#serving-to-an-untrusted-peer-the-channel-principal).

### `serve({ around })`: a per-call wrapper for accepted calls ([#54](https://github.com/CLDMV/slothlet-vine/pull/54), [#51](https://github.com/CLDMV/slothlet-vine/issues/51))

`around: ({ callId, path, args, principal, invoke }) => unknown` receives every call the vine has accepted, after the surface check, after the principal check (inside its scope), and after the args data-only check. It never sees a frame the vine would have refused, and it can't widen what the rules allowed.

- `invoke()` runs exactly the authorized call: it takes no arguments, and each call gets a fresh structured clone of the original arguments.
- `invoke()` can be called more than once, so a transaction can retry on a write conflict.
- `around`'s own `args` is a separate copy, so changing it changes nothing `invoke()` passes.
- `around`'s return value is the call's result and goes through the same data-only return check as a leaf's value; a throw is the call's error.

Events are not wrapped.

## 🔧 CI & tooling

- **Release-merge re-armed on every check-producing workflow** ([#45](https://github.com/CLDMV/slothlet-vine/pull/45)). An approval given before CodeQL or another non-CI check finished no longer leaves the release PR stuck approved and green.
- **Required PR Check can no longer be satisfied early** ([#57](https://github.com/CLDMV/slothlet-vine/pull/57), [#58](https://github.com/CLDMV/slothlet-vine/pull/58)). On an in-repo PR, the skipped `pull_request` mirror job posted `✅ Required PR Check` while tests were still running. It now runs as a no-op under a distinct name, and the required check exists only once the push run's full test matrix has finished.
- **Shared CLDMV fix-headers config** ([#56](https://github.com/CLDMV/slothlet-vine/pull/56)). A `fix:headers` script using `@cldmv/fix-headers` and `@cldmv/configs`, with uniform file headers stamped repo-wide.

## Upgrade notes

- **Requires `@cldmv/slothlet` `>=3.22.0`.** A lower version produces a peer-dependency warning, or an install error under strict peer resolution.
- **No behavior change without the new options.** A serve or grow without `principal` and `around` sends the same frames and produces the same outcomes as v1.1.x; the wire format is unchanged, so a v1.1.x end can talk to a v1.2.0 end.
- **Adopting a principal.**
  - The serving instance needs a `permissions` block. `defaultPolicy: "deny"` is recommended, with rules written against a caller namespace no local module occupies, such as `remote.**`.
  - Run principal-bearing serves on the async (Node) runtime, not `runtime: "live"`.
  - A peer whose call is refused receives a `VineRemoteError` with `.code === "VINE_REMOTE"` and `.remoteCode === "VINE_DENIED"`.
